# 직꾸 SEO 단계별 계획

검색 노출을 **백링크보다 앞서** “키워드 ↔ 페이지” 정합성을 맞추는 것을 최우선으로 한다. 아래는 실행 순서와 산출물 기준 정리다.

---

## 현재 상태에서의 전제

- 홈은 소개 랜딩 1페이지 중심이며, 검색 결과에서는 브랜드명(`직꾸`) 위주로 짧게 보일 수 있다.
- **페이지 1개 = 키워드 1개 = 고유한 `<title>`** 구조가 아직 없다.
- `sitemap.xml`에 등록된 일부 URL이 실제 `app` 라우트와 다를 수 있으므로, **존재하지 않는 URL은 사이트맵에서 제거**하는 것이 인덱싱에 유리하다.

---

## 1단계 — 홈을 대표 키워드 착지로 고정 (최우선)

**목적:** 검색엔진과 사용자에게 “이 사이트의 대표 주제”가 무엇인지 명확히 전달한다.

| 항목 | 방향 |
|------|------|
| `<title>` | 브랜드 + 핵심 키워드 (예: `직꾸 \| 야구 직관 기록 앱 · 직관 다이어리`). 과도한 키워드 나열은 피한다. |
| `meta description` | KBO·직관 기록·일정·사진·메모·승률 등을 한두 문장으로 요약. Google은 서술적이고 간결한 설명을 권장한다. |
| H1 / 히어로 카피 | 메타와 같은 의도로 맞춘다 (브랜드만 강조되지 않게). |
| Open Graph / Twitter | 홈 기준 title·description 동기화, 카드 타입(`summary` vs `summary_large_image`) 통일. |
| 수정 대상 파일 (예시) | `app/layout.tsx`, `app/page.tsx`, `src/pages/introduction/ui/IntroductionPage.tsx` |

---

## 2단계 — 키워드별 전용 페이지 분리 (구조상 가장 중요)

**목적:** “무슨 키워드로 어떤 URL이 대응하는지”를 검색엔진이 구분할 수 있게 한다.

### 제안 URL 예시 (한 페이지 = 한 주제)

| 경로 예시 | 타깃 의도 |
|-----------|-----------|
| `/야구-직관-기록-앱` 또는 `/baseball-attendance-app` | 야구 직관 기록 앱 |
| `/직관-다이어리` | 직관 다이어리 |
| `/kbo-경기-일정` | KBO 경기 일정 / 야구 일정 |
| `/직관-승률` | 직관 승률·통계 |

### 페이지마다 공통으로 할 일

1. `app/.../page.tsx` 추가 및 **페이지별 고유** `metadata` (`title`, `description`, `canonical`).
2. **H1 1개**, 본문·소제목이 해당 키워드 주제에 맞게 작성 (키워드만 반복하지 않는다).
3. 홈·푸터·헤더 등에서 **내부 링크**로 서로 연결.
4. **`app/sitemap.ts`**: 실제 배포된 경로만 포함하고, 없는 구 URL은 제거.

---

## 3단계 — 키워드 우선순위 (콘텐츠·개발 백로그 순서)

1. `야구 직관 기록 앱`, `직관 기록 앱` — 홈 + 필요 시 전용 랜딩
2. `직관 다이어리`
3. `KBO 일정 앱`, `KBO 경기 일정`
4. `직관 승률`
5. 그 다음에만 `야구 팬 앱` 등 **의도가 넓은** 키워드 확장

**이유:** 넓은 키워드는 공식 앱·대형 서비스와 경쟁이 심하고, “직관 기록”처럼 의도가 좁은 키워드부터 포지셔닝하기 쉽다.

---

## 4단계 — 인덱싱 정비 (신규 페이지 반영 후)

| 작업 | 내용 |
|------|------|
| 사이트맵 | 새 URL 추가, 404 가능 URL 삭제 |
| Google Search Console | 사이트맵 제출, URL 검사 |
| 네이버 서치어드바이저 | 사이트맵·RSS(있을 경우) 제출 |
| robots.txt | 루트 유지. 관리자·인증 등 불필요 크롤 경로만 제한 (`/admin/`, `/auth/` 등) |

**주의:** 페이지가 없는데 사이트맵만 길어지면 역효과이므로 **2단계 이후**에 집중한다.

---

## 5단계 — 구조화 데이터 (선택, 홈 또는 앱 소개 허브)

- 서비스 성격상 **`SoftwareApplication`** 스키마 검토 (무료 앱이면 `offers` 등 문서에 맞게 표현).
- 기존 `Organization` / `WebSite` JSON-LD와 **중복·충돌**이 없도록 배치 페이지를 정한다.

**기대 효과:** 순위 직상승이라기보다, “앱 소개” 엔티티로 이해시키는 보조 신호.

---

## 6단계 — 백링크 (그 다음 단계)

- 키워드 랜딩이 정리된 뒤, 블로그·커뮤니티·앱 소개 글에서 **대응 URL로** 자연스럽게 링크한다.
- 착지 페이지가 키워드에 맞지 않으면 링크 효율이 떨어질 수 있으므로 **1~2단계 이후**가 유리하다.

---

## 일정감 (참고)

| 구간 | 내용 |
|------|------|
| 1~2주 | 1단계 완료 + 2단계 중 1~2개 랜딩 초안 |
| 2~4주 | 나머지 랜딩 + 사이트맵·내부 링크 + GSC/네이버 제출 |
| 이후 | 구조화 데이터 보강, 콘텐츠(FAQ 등), 백링크 |

제목·스니펫 반영은 **재크롤 이후 수일~수 주** 걸릴 수 있으므로, **2~4주 단위**로 검색 쿼리·노출 변화를 보는 것이 현실적이다.

---

## 요약

1. **홈**의 title·description·H1을 **대표 키워드(예: 야구 직관 기록 앱)** 중심으로 맞춘다.  
2. **키워드별 전용 페이지**를 나누고 URL·메타·본문을 일치시킨다.  
3. **사이트맵·서치 콘솔**으로 URL을 알린다.  
4. 그다음 **구조화 데이터**, 마지막에 **백링크**를 확대한다.
