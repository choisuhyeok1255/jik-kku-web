# 직꾸 SEO 작업 명세서 v2

이 문서는 **Cursor**에서 바로 작업할 수 있도록 만든 SEO 수정 명세서입니다.  
대상 사이트는 `https://www.jik-kku.com/` 이며, 페이지는 총 4개입니다.

- 홈
- 직관 기록
- 하이라이트
- 경기 일정

---

## 1. 작업 목표

이번 작업의 목표는 다음과 같습니다.

1. 각 페이지의 역할에 맞는 **대표 키워드 / 보조 키워드**를 명확히 나눈다.
2. 페이지별 `title`, `meta description`, `H1`, 본문 첫 문단, FAQ, 내부링크 문구를 키워드 전략에 맞게 정리한다.
3. 검색엔진이 각 페이지를 서로 다른 주제로 이해할 수 있도록 만든다.
4. `앱`, `다이어리` 중심 표현은 최소화하거나 제외하고, **행동/주제 중심 키워드**로 조정한다.
5. 하이라이트 페이지는 일반 키워드 위주로 유지하고, 팀명 키워드 과도 삽입은 하지 않는다.
6. 경기 일정 페이지는 **단순 일정 조회 기능 설명 페이지**로 유지한다. 일정 확인 후 바로 기록 작성이 가능한 것처럼 쓰면 안 된다.

---

## 2. 핵심 SEO 원칙

### 유지할 방향
- `앱` 중심보다 **야구 직관 / 직관 기록 / 하이라이트 / 경기 일정** 중심으로 작성
- 페이지마다 **대표 키워드 1개 + 보조 키워드 3~5개** 정도로 운영
- 동일 키워드를 전 페이지에 반복 배치하지 않고 페이지 역할에 따라 분산
- 키워드 나열식 문장 금지
- 사용자에게 자연스럽게 읽히는 문장 우선

### 제외할 방향
- `다이어리` 관련 표현 전체 제외
- `앱` 강조형 키워드 제외 또는 최소화
- 하이라이트 페이지에 `구단명 + 경기 다시보기`를 전부 나열하는 방식 금지
- 경기 일정 페이지에서 직관 기록으로 바로 이어지는 기능이 있는 것처럼 쓰는 표현 금지

---

## 3. 페이지별 키워드 전략

### 3-1. 홈
**페이지 역할**  
서비스 전체를 소개하는 페이지

**대표 키워드**
- 야구 직관 기록

**보조 키워드**
- 야구 직관
- 직관 기록
- 야구 경기 기록

**적용 방향**
- 홈은 서비스 전체를 설명하는 페이지로 유지한다.
- 가장 넓은 검색 의도를 받는 페이지로 설정한다.
- 특정 기능 페이지처럼 보이지 않도록 한다.
- “야구 직관을 기록하는 서비스”라는 큰 주제를 중심으로 작성한다.

**피해야 할 것**
- 하이라이트 기능, 경기 일정 기능을 홈의 중심 주제로 밀어 올리는 것
- `앱`, `다이어리` 중심 표현

---

### 3-2. 직관 기록 페이지
**페이지 역할**  
직관 기록을 어떻게 남기는지 설명하는 기능 페이지

**대표 키워드**
- 직관 기록

**보조 키워드**
- 야구 직관 기록
- 야구 경기 기록
- 직관 기록 방법
- 직관 기록 남기기

**적용 방향**
- 기록 행위 자체에 집중한다.
- 무엇을 기록할 수 있는지, 어떻게 기록하는지, 얼마나 쉽게 기록할 수 있는지 설명한다.
- 서비스 전체 소개가 아니라 기능 설명 페이지 톤으로 작성한다.

**피해야 할 것**
- 홈처럼 서비스 전체 소개 느낌으로 쓰는 것
- 하이라이트 / 일정 키워드가 메인이 되는 것

---

### 3-3. 하이라이트 페이지
**페이지 역할**  
직관 기록한 경기의 하이라이트 영상을 자동 연결해 쉽게 볼 수 있는 기능 설명 페이지

**대표 키워드**
- 야구 하이라이트

**보조 키워드**
- 경기 하이라이트
- 직관 하이라이트
- 경기 다시보기
- 기록한 경기 하이라이트

**적용 방향**
- 단순 하이라이트 모음 페이지처럼 보이지 않게 한다.
- 직관 기록과 연결된 하이라이트 기능이라는 점을 중심으로 설명한다.
- 일반 키워드 위주로 구성한다.

**피해야 할 것**
- `기아 경기 다시보기`, `한화 경기 다시보기`, `LG 경기 다시보기` 같은 팀명 조합을 한 페이지에 대량 나열하는 것
- 팀명 키워드를 메타 태그나 제목에 과도하게 넣는 것

**팀명 키워드 운영 기준**
- 팀명은 필요하다면 본문 예시, FAQ, 자연스러운 설명 문장 안에서만 제한적으로 사용한다.
- 팀명 키워드를 메인 SEO 타깃으로 삼지 않는다.

---

### 3-4. 경기 일정 페이지
**페이지 역할**  
각 구단별 경기 일정, 상대팀, 경기 구장을 확인할 수 있는 기능 설명 페이지

**대표 키워드**
- KBO 경기 일정

**보조 키워드**
- 구단별 경기 일정
- 야구 경기 일정
- 팀별 경기 일정
- 경기 일정 확인
- 경기 구장 확인
- 날짜별 경기 일정
- 상대팀 확인

**적용 방향**
- 일정 조회 기능 자체에 집중한다.
- 사용자가 원하는 날짜의 경기 정보, 상대팀, 경기 구장을 쉽게 확인할 수 있다는 점을 설명한다.
- 일정 확인 기능 설명 페이지로 유지한다.

**중요 주의사항**
- 현재 이 페이지는 일정 조회만 가능하다.
- 이 페이지를 기반으로 바로 직관 기록을 작성하는 기능은 제공하지 않는다.
- 따라서 “일정 확인 후 바로 기록”, “일정에서 바로 직관 기록 작성” 같은 표현을 사용하면 안 된다.

**피해야 할 것**
- 직관 기록으로 직접 이어지는 기능이 있는 것처럼 보이게 쓰는 것
- 일정 페이지에서 기록 기능 설명이 중심이 되는 것

---

## 4. 메타데이터 작성 규칙

### 4-1. title 규칙
- 각 페이지의 대표 키워드를 맨 앞쪽에 배치
- 필요하면 보조 키워드 1개 정도만 자연스럽게 포함
- 브랜드명 `직꾸`는 뒤쪽에 배치
- 과도한 키워드 나열 금지
- 너무 짧거나 너무 길지 않게 작성

예시 방향:
- 홈: `야구 직관 기록 | ... | 직꾸`
- 직관 기록: `직관 기록 | ... | 직꾸`
- 하이라이트: `야구 하이라이트 | ... | 직꾸`
- 경기 일정: `KBO 경기 일정 | ... | 직꾸`

### 4-2. meta description 규칙
- 대표 키워드 1회 포함
- 보조 키워드 1~2개 자연스럽게 포함
- 기능 설명 문장 중심
- 키워드 나열형 문장 금지

### 4-3. H1 규칙
- 대표 키워드 중심
- title보다 조금 더 자연스럽고 사용자 친화적인 문장으로 작성
- 페이지 주제가 즉시 이해되게 작성

### 4-4. 첫 문단 규칙
- 첫 1~2문장 안에 대표 키워드 포함
- 이 페이지가 무엇을 설명하는지 바로 드러나게 작성

---

## 5. 내부링크 문구 규칙

내부링크 앵커텍스트도 키워드 전략에 맞게 수정한다.

### 예시
- 홈 → 직관 기록 페이지: `직관 기록 방법 보기`
- 홈 → 하이라이트 페이지: `야구 하이라이트 기능 보기`
- 홈 → 경기 일정 페이지: `KBO 경기 일정 확인하기`
- 직관 기록 페이지 → 하이라이트 페이지: `기록한 경기의 하이라이트 보기`

### 금지 예시
- `여기 클릭`
- `자세히 보기`만 단독 사용
- 실제 기능과 다르게 오해할 수 있는 문구
  - 예: `일정에서 바로 직관 기록하기`

---

## 6. FAQ 작성 규칙

각 페이지에 2~4개 정도 FAQ를 넣는다.  
FAQ는 보조 키워드를 자연스럽게 흡수하는 역할을 한다.

### 홈 FAQ 예시 방향
- 야구 직관 기록은 어떻게 남길 수 있나요?
- 직관 기록으로 어떤 정보를 정리할 수 있나요?

### 직관 기록 페이지 FAQ 예시 방향
- 직관 기록은 어떻게 남기나요?
- 야구 경기 기록으로 어떤 내용을 저장할 수 있나요?

### 하이라이트 페이지 FAQ 예시 방향
- 기록한 경기의 하이라이트를 다시 볼 수 있나요?
- 경기 다시보기는 어떻게 연결되나요?

### 경기 일정 페이지 FAQ 예시 방향
- KBO 경기 일정은 어떻게 확인하나요?
- 구단별 경기 일정과 경기 구장을 함께 볼 수 있나요?
- 날짜별 경기 일정에서 상대팀도 확인할 수 있나요?

## 7. 기술 SEO 작업 범위

다음 항목도 함께 점검 및 수정한다.

### 7-1. canonical
- 각 페이지에 자기 자신을 가리키는 canonical 설정
- 중복 URL이 있다면 대표 URL 기준으로 정리

### 7-2. Open Graph
- 각 페이지별 `og:title`, `og:description`, `og:url` 점검
- 일반 메타데이터와 방향 일치

### 7-3. sitemap
- 홈, 직관 기록, 하이라이트, 경기 일정 페이지가 모두 sitemap에 포함되는지 확인

### 7-4. robots
- 검색엔진 수집 차단 요소가 없는지 점검

### 7-5. 구조화 데이터
- 가능하다면 `WebSite`, `WebPage` 수준에서 기본 구조화 데이터 점검
- 과도한 마크업은 넣지 말고, 현재 페이지 설명 구조에 맞게 최소한으로 적용

---

## 8. Next.js App Router 작업 가이드

프로젝트가 App Router 기준이라면 각 페이지의 `metadata`를 페이지 성격에 맞게 개별 설정한다.

예시 작업 범위:
- `app/page.tsx` 또는 홈 라우트 metadata 수정
- `app/.../page.tsx` 개별 페이지 metadata 수정
- title / description / openGraph / alternates.canonical 점검
- sitemap 생성 로직이 있다면 세부 페이지 반영 여부 확인

---

## 9. 실제 문구 작성 시 주의사항

### 반드시 지킬 것
- 기능 설명이 실제 서비스 동작과 일치해야 한다.
- 과장 표현 금지
- 없는 기능을 있는 것처럼 쓰지 말 것
- 한 페이지에 너무 많은 키워드를 몰아넣지 말 것
- 사람이 읽었을 때 자연스러운 문장으로 작성할 것

### 특히 경기 일정 페이지 주의
현재 기능은 아래까지만 설명 가능하다.
- 구단별 경기 일정 확인
- 날짜별 일정 확인
- 상대팀 확인
- 경기 구장 확인

설명하면 안 되는 것:
- 일정에서 바로 기록 작성
- 일정 기반 자동 기록 생성
- 일정과 기록이 직접 연결되는 흐름

## 10. Definition of Done

다음 조건을 충족하면 작업 완료로 본다.

1. 4개 페이지 각각의 title, meta description, H1, 첫 문단이 페이지별 키워드 전략에 맞게 수정되어 있다.
2. `다이어리` 관련 표현이 제거되어 있다.
3. `앱` 중심 표현이 불필요하게 반복되지 않는다.
4. 하이라이트 페이지에 팀명 키워드가 과도하게 삽입되어 있지 않다.
5. 경기 일정 페이지에 실제 제공하지 않는 “기록 연동 기능”이 암시되지 않는다.
6. 내부링크 문구가 페이지 역할과 맞게 정리되어 있다.
7. sitemap / canonical / OG 등 기본 메타 요소가 점검되어 있다.

## 11. Cursor 작업 지시문

아래 내용을 Cursor에 직접 전달해서 작업한다.

```md
직꾸 사이트의 SEO 문구와 메타데이터를 페이지 역할에 맞게 수정해줘.

대상 페이지는 4개야.
1. 홈
2. 직관 기록
3. 하이라이트
4. 경기 일정

전체 방향은 아래와 같아.
- `앱` 중심 표현보다 행동/주제 중심으로 수정
- `다이어리` 관련 표현은 제외
- 각 페이지마다 대표 키워드 1개와 보조 키워드 3~5개 정도만 자연스럽게 반영
- 키워드 나열식 문장 금지
- 실제 기능과 다른 표현 금지

페이지별 키워드 전략은 아래를 따라줘.

[홈]
- 대표 키워드: 야구 직관 기록
- 보조 키워드: 야구 직관, 직관 기록, 야구 경기 기록
- 서비스 전체 소개 페이지로 유지

[직관 기록]
- 대표 키워드: 직관 기록
- 보조 키워드: 야구 직관 기록, 야구 경기 기록, 직관 기록 방법, 직관 기록 남기기
- 직관 기록을 어떻게 남기는지 설명하는 기능 페이지

[하이라이트]
- 대표 키워드: 야구 하이라이트
- 보조 키워드: 경기 하이라이트, 직관 하이라이트, 경기 다시보기, 기록한 경기 하이라이트
- 기록한 경기의 하이라이트를 자동 연결해 쉽게 볼 수 있는 기능 설명 페이지
- 구단명 + 경기 다시보기 키워드를 대량으로 넣지 말 것

[경기 일정]
- 대표 키워드: KBO 경기 일정
- 보조 키워드: 구단별 경기 일정, 야구 경기 일정, 팀별 경기 일정, 경기 일정 확인, 경기 구장 확인, 날짜별 경기 일정, 상대팀 확인
- 각 구단별 경기 일정, 상대팀, 경기 구장을 확인하는 기능 설명 페이지
- 현재는 단순 일정 조회 기능만 제공하므로 일정에서 바로 직관 기록을 작성하는 것처럼 보이게 쓰면 안 됨

수정 범위는 아래와 같아.
- 각 페이지 metadata(title, description, openGraph, canonical)
- H1
- 첫 문단
```
